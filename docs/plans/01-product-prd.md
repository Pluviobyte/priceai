# 产品需求：AI 订阅价格情报与渠道核验平台

## 1. 产品定义

一个面向 AI 订阅、账号、充值和数字权益的价格情报平台。系统持续从公开原站采集价格、库存、交付方式和售后信息，将不同渠道的原始商品标准化为可比较的权益产品，并保留来源、新鲜度、历史和风险事实。平台不参与交易，用户最终回到原商家完成购买。

## 2. 对标范围

功能层面对标 PriceAI 的四个频道：

1. **卡网订阅**：第三方店铺的 AI 账号、代充、卡密、拼车等报价。
2. **官方订阅**：App Store、Google Play 和官网直购地区价格。
3. **官方 API**：模型厂商官方 token、图片、视频等计费标准。
4. **中转 API**：第三方 API 中转站倍率、价格、来源和稳定性。

不复制：PriceAI 名称、Logo、插画、广告素材、页面文案、CSS 和私有代码。

## 3. 用户问题

- 同一个 AI 权益在哪里购买更便宜？
- 最低价是成品号、自己账号充值、拼车还是反代？
- 商品是否有货，数据什么时候在原站最后确认？
- 商家是否提供质保，质保只保首登还是覆盖订阅期？
- 报价和官方价格相比便宜多少，风险差异是什么？
- 某个低价是真实商品，还是价格解析、库存或分类错误？
- 某个 API 中转站价格低的同时是否稳定？

## 4. 产品原则

### 4.1 发现来源不等于事实来源

X、Grok、搜索引擎、用户投稿和竞品 feed 只用于发现新渠道。正式价格的证据优先级为：

```text
原店铺公开 API
> 原店铺公开 HTML/内嵌 JSON
> 商家标准 Feed
> 浏览器核验的公开页面
> 其他聚合平台快照
> 人工临时补录
```

### 4.2 不混淆不同购买意图

“ChatGPT Plus”不是一个可直接比较的单一 SKU。至少要同时描述：

- 权益产品；
- 购买/交付方式；
- 使用期限；
- 账号归属；
- 接码状态；
- 质保方式；
- 是否共享；
- 网页、客户端、API 可用性。

### 4.3 展示风险事实，不给模糊信用背书

平台不声称某商家“绝对可靠”，而是展示可以从商品原文或公开证据中确认的事实：无质保、只保首登、需要交出账号密码、共享、不可网页使用、仅反代、不可囤、是否提供 2FA 等。

## 5. 用户角色

| 角色 | 主要能力 |
|---|---|
| 普通访客 | 搜索、筛选、比价、查看来源和跳转原站 |
| 投稿用户/商家 | 提交店铺 URL、主营商品、联系方式和 Feed 信息 |
| 数据运营 | 审核来源、纠正分类、处理异常和举报 |
| 系统管理员 | 管理适配器、调度、发布、权限和广告 |

## 6. 前台页面

### P0 页面

| 页面 | 核心内容 |
|---|---|
| 首页 | 搜索、热门权益产品、最低有货价、质保最低价、数据更新时间 |
| 平台页 | ChatGPT、Claude、Gemini、Grok 等品牌分类 |
| 商品详情页 | 原始报价表、筛选、排序、来源、库存、新鲜度和风险事实 |
| 商家详情页 | 店铺入口、发卡系统、商品数、最后成功、首次发现、采集健康 |
| 渠道目录 | 已收录店铺、状态、覆盖产品与申请收录入口 |
| 渠道提交 | URL、名称、联系方式、主营商品、Feed/API 意愿 |
| 举报纠错 | 价格错误、虚假库存、商品下架、分类错误、商家异常 |
| 数据说明 | 来源等级、采集频率、过期规则、排序口径、免责说明 |

### P1 页面

- 官方订阅地区价与套餐详情；
- 价格历史、库存历史；
- 降价与补货订阅；
- 商家价格稳定性；
- 公开采集健康页；
- 可下载或只读公共数据 API。

### P2 页面

- 官方 API 模型与供应商目录；
- 中转 API 站点、模型倍率和固定套餐；
- 成功率、延迟、TPS 和监测时间线；
- 中转站公告和维护事件；
- 用户自带 API Key 的一次性检测工具。

## 7. 商品详情核心交互

报价表至少展示：

- 当前价格与币种；
- 原始商品标题；
- 商家/店铺；
- 库存状态和数值库存（如果有）；
- 最后成功确认时间；
- 最近检查结果；
- 交付方式、期限、质保、账号归属等属性；
- 风险事实；
- 原站购买链接。

筛选至少包括：

- 在售/缺货；
- 新鲜/即将过期/已过期；
- 自己账号充值/成品号/卡密/拼车/反代；
- 使用期限；
- 长期质保/首登质保/无质保；
- 已接码/未接码；
- 共享/独享；
- 网页可用/客户端可用/API 可用。

默认排序：有效且新鲜的可购买报价优先，再按可比规格下的价格升序。共享、镜像、仅网页、短期日抛等不同购买意图不能挤占普通正价订阅的默认最低价。

## 8. 管理后台

### 来源工作台

显示：店铺、系统类型、采集器、最后检查、最后成功、连续失败、商品数、与上次差异、耗时、错误、下次运行。

操作：试采集、完整重抓、暂停、切换适配器、查看原始响应、查看历史、标记下架、加入适配器待办。

### 异常工作台

- 有货但库存为零；
- 商品数突然下降；
- 极端低价或币种错误；
- API 分页不完整；
- 相同源商品出现冲突价格；
- 页面变成验证码/WAF/登录页；
- 分类低置信度或信号冲突；
- 商品 URL 跳到不同商家。

### 分类工作台

运营纠正应生成 `manual_override`、`rule_patch` 或 `alias_patch`，不能修改或覆盖原始事实。规则更新后可对历史商品重新分类。

### 投稿与举报工作台

```text
待审核
→ URL 安全检查
→ 自动识别发卡系统
→ 试采集并预览前 10 条商品
→ 审核通过 / 待开发适配器 / 拒绝
```

## 9. 商业化

可选方式：赞助位、明确标注的联盟链接、商家数据直连服务、专业数据 API。

约束：

- 赞助内容必须标注“赞助/推广”；
- 自然排名不得包含商业付费权重；
- 商业关系记录到具体来源或广告位；
- 普通报价链接和联盟链接应在数据层区分；
- 平台不代收商品款，不为第三方交易担保。

## 10. 非目标

- 不代用户购买、不托管账号、不处理充值资金；
- 不绕过验证码、登录、付费墙或 WAF；
- 不抓取需要私人账号权限的数据；
- 不在第一版构建社区、资讯、在线聊天或综合 AI 门户；
- 不在第一版追求上千店铺，先保证正确性。

## 11. 首版成功指标

- 接入 3 类主流发卡系统；
- 30–50 个高质量来源；
- 10–15 个核心权益产品；
- 价格解析抽样准确率不低于 99.5%；
- 完整采集失败不会清空旧数据；
- 库存冲突和异常价不参与最低价；
- 商品改价不会生成新的商品身份；
- 每条公开报价都能回溯到原始来源和确认时间。

# 发布后的维护窗口

持续 Channel Worker 每次成功完成发布后，至少等待 `CHANNEL_PUBLISH_COOLDOWN_MS` 才开始下一次发布，默认 30000ms。配置接受 0–60000ms；0 恢复原调度行为，非法值使用默认值。

窗口开始前发布事务已经提交，发布锁已释放。采集与准入调度继续运行，新变化合并到待发布计数，不会因达到三个变化而绕过窗口。日志事件 `publication_maintenance_window` 标出窗口配置时长。首次发布不额外延迟；发布失败保留原重试逻辑；正常关闭时的最终 flush 为避免丢失待发布变更，可跳过窗口。

这不是清理授权或资源豁免。维护程序仍必须在每批事务中取得共享发布锁，保护当前、上一、固定及其他保留版本，并检查资源和服务状态。窗口不保证一定有删除：资源不足时应让窗口空过。

上线只需替换 Channel Worker 镜像；不需要数据库迁移、修改 Web 标题或调整其他服务。验证成功发布日志后至少30秒没有下一轮发布事务，并确认期间采集继续、维护批次可在窗口取得锁。回退使用原 Channel Worker 镜像，或将该环境变量持久设为0后重建该 Worker。

# 官方订阅页面性能修复（2026-09-09）

## 原因与变更

官方订阅总览下方的地区矩阵默认渲染 13 套餐 × 3 渠道 × 174 地区，共 6,786 个价格单元格，包含每格的来源和检查说明。线上完整 HTML/RSC 解压后约 14.4 MB，且没有路由加载状态，等待时容易误以为导航没有响应。

- 对照矩阵每页只渲染 10 个地区，`compare_page` 为页码；保留所有地区的选择入口。
- 翻页保留搜索和对照筛选，选择地区或重新提交筛选时回到第一页；非法页码回到第一页，越界页码收敛到末页。
- 范围统计、较低价标记仍按筛选范围内全部地区计算，分页不改变比较口径。
- `official-prices/loading.tsx` 提供可预加载的路由加载状态，保留公共导航。
- 价格和采集检查并发读取；总览和地区详情使用共享快照，每次请求只读一次检查数据。没有跨请求缓存，也没有放宽价格有效性要求。

## 验证

同一隔离数据库中生成 174 地区、7,308 条演示报价。对照表组件的 `renderToStaticMarkup` 对照结果（不含页面其他区域和 RSC）：

| 指标 | 原实现 | 优化后 |
|---|---:|---:|
| 价格格子 | 6,786 | 390 |
| HTML 字节 | 6,139,049 | 372,175 |
| 本地单次渲染耗时 | 771 ms | 166 ms |

本地生产构建完整总览响应 1,438,337 字节；首次测量首段 109 ms、完整响应 294 ms，后续翻页完整响应 182 ms。响应首段含加载提示。这些是本地演示数据测量，不代表线上延迟承诺。

浏览器确认翻页显示第 2 / 18 页、地区 11–20，并可直接选择美国；重新请求期间显示加载提示。前台真实数据未修改。

回归测试包含实际组件渲染大小/单元格上限、跨页较低价不变、筛选保留、页码边界，以及数据库查询并发与单次检查读取、失败状态。

```sh
npm run test --workspace @price-radar/web
npm run build --workspace @price-radar/web
```

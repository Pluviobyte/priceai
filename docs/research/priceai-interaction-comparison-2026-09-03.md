# PriceAI 交互、引导与功能对比

调研日期：2026-09-03  
对标站点：https://priceai.cc/  
本地站点：http://localhost:3000/

## 调研范围

实际打开并检查了 PriceAI 的首页、卡网订阅、ChatGPT Plus 商品详情、官方订阅、官方 API、中转 API 与指南；同时逐页核对本地首页、来源目录、商品详情、官方订阅、官方 API、中转 API、数据说明、系统健康和渠道提交。

## PriceAI 的核心交互模型

1. 首页不承担完整比价，先按用户意图分流：订阅新手、低价买家、开发接入。
2. 第二层使用四个稳定频道：卡网订阅、官方订阅、官方 API、中转 API。
3. 卡网订阅先展示标准商品目录，再进入单个商品的原始报价表。
4. 商品详情把库存、渠道、原始商品名、价格、更新时间、风险、购买和反馈放在同一张高密度表格中。
5. 筛选采用“快捷特征 + 展开高级筛选”：库存阈值、更新时间、商品特征、来源、价格区间、包含与排除关键词。
6. 每个频道在主工具前提供简短买前指南，并从结果页继续导向相关指南。
7. 官方订阅按标准商品、地区和周期聚合；官方 API 按厂商与订阅或 Token Plan 展示；中转 API 同时展示倍率、稳定性、样本量、延迟和来源披露。
8. 全站反复声明平台不卖货、不担保，用户最终回到原站核验和交易。

## 本地站相对更强的能力

- 原始标题、原始价格文本、来源、确认时间和风险事实的证据链更完整。
- 商品详情已经具备交付方式、质保、账号归属、库存、共享、接码、期限与排序筛选。
- 官方价格证据明确区分精确、区间和未知，不把区间价参与最低价。
- 商品详情已经具备官方价对照、降价/补货提醒和价格库存历史。
- 中转 API 已有一次性自带 Key 检测，并明确 Key 不落库、不写日志和 Cookie。
- 有公开系统健康页、公共只读 API、举报与商家退出收录流程。

## 仍需继续补齐

1. 卡网订阅的“全部报价”独立视图和更大规模分页。
2. 同名、同店、同规格报价折叠，减少重复行。
3. 商品详情的包含/排除关键词、价格区间、来源类型与更新时间阈值筛选。
4. 中转 API 的充值系数、模型倍率、综合倍率、缓存命中率和模型真实性报告。
5. 独立指南内容中心，以及从商品和频道页到具体指南文章的深链接。
6. 深色模式、公告、社区入口和用户登录属于增长能力，不是当前比价闭环的稳定性前提。

## 设计与实现原则

- 学习 PriceAI 的信息架构和任务流程，不复制名称、Logo、插画、文案、CSS 或私有代码。
- 首页优先解决“该去哪个频道”，频道页负责比较，详情页负责核验与跳转。
- 新增交互优先采用 URL 查询参数和服务端渲染，便于分享、SEO、回退和稳定运行。
- 移动端保留所有主要入口，不用隐藏导航解决空间问题。
- 状态始终同时提供文字与颜色，避免只靠颜色表达库存、风险或证据等级。

# AI 订阅比价竞品交互审计与融合方案

调研对象：[AI比价](https://aibijia.org/)、[RelayWatch](http://relaywatch.online/)、[AI号探](https://www.aihaotan.com/#home)  
调研日期：2026-09-03

## 结论摘要

三个站点各自解决了一个关键问题：AI比价擅长快速切换购买渠道并比较官方地区价；RelayWatch擅长把 API 服务商的模型、成功率、延迟和证据摊开；AI号探擅长新手搜索引导、价格异动与社区反馈。

当前 AI 价格雷达在“同规格归一、来源追溯、风险事实、官方价基准”上更扎实，但此前缺少三个高频效率工具：价格区间、可量化的中转筛选，以及跨商品的价格/库存异动。本轮已经将这三类能力融合，并保留现有证据边界。

## 逐站交互审计

### 1. AI比价

公开交互包括：顶部外链；发卡平台/官方订阅分段切换；ChatGPT、Gemini、Claude Code、Grok 快速切换；商品关键词和最低/最高价筛选；官方方案切换；App Store 地区表格；最低价、人民币估算和价差提示；国家商店直达；AI 资讯浮层；提交平台抽屉与进度文案。

它做得更好的地方：

- “发卡平台”和“官方订阅”在同一任务上下文中切换，用户很容易理解两种购买路径。
- 价格区间是卡网用户最直接的筛选手段。
- 官方地区价同时展示原币、汇率、人民币估算、最低地区和价差，扫读效率高。
- 投稿抽屉让用户不必离开当前页面即可贡献来源。

不建议照搬：

- 关键词采用宽松子串命中，会把“不含 plus”等反向语义放进结果。
- 会员、账号、API、共享等不同交付物仍有混在同一结果集的风险。
- 大面积装饰性首屏和资讯浮层挤占比价任务空间。
- 窄视口仍呈现明显桌面布局，移动端操作成本高。

### 2. RelayWatch

公开交互包括：全局搜索；提交与刷新；公告关闭；站点/模型/卡网三个比价频道；状态、供应商、计费类型、目标模型、排序和分页筛选；卡片/列表视图；站点详情抽屉；模型价格、成功率、延迟、TPS 与样本数；官方 API 状态；公告时间线；站点真假、质量和在线对话工具；站点与卡网分开的提交表单；数据采集与更新流程说明。

它做得更好的地方：

- 成功率、延迟、样本数与模型价格同屏，用户可以用证据筛服务商，而不是只看倍率。
- 详情抽屉保留当前列表上下文，又能查看模型级明细。
- 工具页清楚说明 API Key 不保存、报告范围和检测阶段，安全预期较明确。
- “发现、采集、归一、索引、更新”的流程解释增强了数据可信度。

不建议照搬：

- 巨大的供应商和模型下拉列表让筛选器本身成为负担。
- 页面数据密度过高，缺乏从新手任务到专家指标的渐进披露。
- 全局搜索输入后的反馈不够明确。
- 页数极多、缺失值多，容易让规模感压过可用性。
- 移动端仍接近桌面宽表。

### 3. AI号探

公开交互包括：首次免责声明；首页推荐位披露；商品搜索；示例、最近搜索与热词；价格和库存排序；商品详情弹窗；风险确认后跳转；店铺搜索；评论提交及审核说明；价格/销量异动；多档时间窗口；店铺提交；举报和证据上传；曝光台；分享当前搜索；响应式移动布局。

它做得更好的地方：

- 搜索示例和热词让第一次来的用户不需要猜关键词。
- 点击示例后立即进入结果，路径短。
- 商品详情在跳转前再次展示原始描述和风险提示。
- 异动页让用户从“找最低价”转向“判断现在是否值得买”。
- 提交、举报、评论和曝光台形成了较完整的用户反馈闭环。
- 390px 下搜索、导航和商品卡片能正确重排。

不建议照搬：

- 首次访问强制免责声明阻断核心任务，用户尚未获得价值就先承担阅读成本。
- 商品缩略图来源不一，视觉噪声大且不能增加价格可信度。
- 搜索召回高但精度不足，例如 team 可能带出非 AI 商品。
- 重复库存免责声明和过长商家描述削弱了信息层级。

## 与当前产品的差距矩阵

| 用户任务 | 竞品最佳做法 | 当前原有能力 | 本轮决策 |
|---|---|---|---|
| 快速找到常见产品 | AI号探示例与热词 | 只有搜索框 | 融合快捷搜索词，直接进入标准商品结果 |
| 控制预算 | AI比价最低/最高价 | 商品页只能按价格排序 | 在商品聚合页与详情页加入价格区间 |
| 找库存更充足的报价 | AI号探库存排序 | 只支持可购买过滤 | 加入库存从多到少排序 |
| 判断中转稳定性 | RelayWatch成功率、延迟、样本阈值 | 仅展示指标与排序 | 加入成功率、最大延迟、有样本筛选，并支持搜模型 |
| 找可信来源 | RelayWatch多维来源筛选 | 渠道目录无筛选 | 加入名称、状态、启用状态和排序 |
| 发现降价与补货 | AI号探多窗口异动 | 仅在单商品页看历史 | 新增全站价格/库存异动页 |
| 选择反馈入口 | AI号探提交与举报分流 | 提交页只有新店铺表单 | 增加新增店铺、纠错举报、商家直连三路引导 |
| 首次风险教育 | 多站弹窗或大段说明 | 页面内风险事实与方法说明 | 保持非阻断式提示，不复制强制弹窗 |

## 已融合到本地产品的功能

1. 卡网订阅页新增最低价、最高价、推荐/最低价/有质保最低/报价最多排序，以及常搜产品快捷入口。
2. 商品详情新增价格区间和库存排序，继续与交付方式、质保、账号归属等规格筛选组合。
3. API 中转页可搜索模型名称，并按近 7 日最低成功率、最大延迟和是否有监测样本过滤。
4. 渠道目录新增商家/网址搜索、连接状态、启用状态及最近成功/商品数/名称排序。
5. 新增“价格与库存异动”频道，提供 24 小时、7 天、30 天与价格/库存类型切换。每条记录都回链商品和商家。
6. 首页加入热门搜索词和异动入口；提交页增加三类任务分流。
7. 新增交互均使用 URL 参数，可收藏、分享、后退，并由服务端渲染；无 JavaScript 时核心筛选仍可用。

## 稳定性设计

- 异动来自同一报价的历史观测，不用不同商家的不同规格商品相互做差。
- 价格区间与排序复用当前已发布、非隔离报价。
- 中转阈值明确限定为近 7 日平台监测；没有样本的服务商不会被伪装成 0% 或 100%。
- 搜索不仅匹配站点名，也匹配该站公开模型代码，但仍保留标准商品归一作为订阅搜索主入口。
- 所有筛选使用白名单参数；周期仅允许 1、7、30 天。
- 390px 移动端将复杂工具栏和异动行重排为单列，不依赖横向宽表完成核心任务。

## 后续优先级

下一阶段可考虑“非阻断式购买确认抽屉”和“已审核评论摘要”，但前者需要可靠地展示原始商品快照，后者需要账号、审核、滥用防护和申诉机制。现阶段不应为了复制竞品表面功能而仓促上线。

## 调研限制

本次只覆盖公开、未登录交互，没有绕过验证码或访问后台。统计数字与页面内容是调研当日快照。三个站点的强项被按 AI 价格雷达的目标用户任务重新组合，并非逐像素复制。
